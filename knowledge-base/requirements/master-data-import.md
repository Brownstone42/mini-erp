# Master Data Import Requirements

สถานะ: Discovery

## เป้าหมายระยะแรก

ผู้ใช้สามารถนำข้อมูล Supplier และ Customer ที่ Export จาก Express เข้าสู่ ERP ใหม่ได้

## ขอบเขตเบื้องต้น

- Supplier master data
- Customer master data
- Upload ไฟล์ต้นทาง
- Preview และตรวจสอบข้อมูลก่อนนำเข้า
- รายงานรายการที่นำเข้าได้และรายการที่มีปัญหา

## โครงสร้างเมนูที่ยืนยันแล้ว

- `Master Data` เป็นเมนูหลักสำหรับข้อมูลหลักของ ERP และต้องรองรับเมนูย่อยเพิ่มเติมในอนาคต
- `Supplier` และ `Customer` เป็นเมนูย่อยแยกจากกัน
- หน้าและ flow การ Upload ของ Supplier และ Customer ต้องแยกจากกัน ไม่ใช้หน้า Import รวม

## Requirement ที่ยืนยันแล้ว

- Supplier ต้องใช้รหัสเดิมจาก Express เป็นรหัส Supplier ใน ERP ใหม่ เช่น `AP00001`
- ระบบ Import ต้องรักษารหัสเดิมโดยไม่สร้างหรือแทนที่ด้วยรหัสใหม่
- รหัส Supplier จาก Express ต้องไม่ซ้ำและต้องไม่ว่าง
- หากรหัส Supplier มีอยู่แล้วใน ERP ระบบต้องอัปเดต Supplier เดิมจากข้อมูลในไฟล์ใหม่
- หากยังไม่มีรหัส Supplier ใน ERP ระบบต้องสร้าง Supplier ใหม่ด้วยรหัสดังกล่าว
- ทุก field ที่อยู่ในขอบเขตการ Import ต้องใช้ค่าจากไฟล์ Express ล่าสุดเป็นหลัก
- ค่าว่างในไฟล์ Express ต้องเขียนทับและล้างค่าเดิมใน ERP สำหรับ field ที่อยู่ในขอบเขตการ Import
- ผลการ Import ต้องแยกจำนวนรายการที่สร้างใหม่ อัปเดต และไม่สำเร็จ
- ระบบต้องไม่เก็บไฟล์ CSV ต้นฉบับหลังจากกระบวนการ Import สิ้นสุด
- หลัง Upload ระบบต้องแสดง Preview และผลตรวจสอบก่อน โดยยังไม่เปลี่ยนข้อมูล Supplier
- ระบบจะสร้างหรืออัปเดต Supplier ต่อเมื่อผู้ใช้กดยืนยัน Import เท่านั้น
- หน้า Preview ต้องสรุปจำนวนรายการที่จะสร้างใหม่ อัปเดต และรายการที่มีข้อผิดพลาด
- หน้า Preview เป็นแบบอ่านอย่างเดียว ผู้ใช้แก้ไขข้อมูลจากไฟล์บนหน้าจอไม่ได้
- หากข้อมูลไม่ถูกต้อง ผู้ใช้ต้องกลับไปแก้ใน Express แล้ว Export และ Upload ไฟล์ใหม่
- หากพบข้อผิดพลาดแม้แต่หนึ่งรายการ ระบบต้องบล็อกการ Import ทั้งไฟล์
- ระบบต้องไม่สร้างหรืออัปเดต Supplier บางส่วนจากไฟล์ที่มีข้อผิดพลาด
- การยืนยัน Import ต้องสำเร็จทั้งชุด หรือยกเลิกการเปลี่ยนแปลงทั้งหมดเมื่อเกิดข้อผิดพลาดระหว่างดำเนินการ
- Supplier ที่มีอยู่ใน ERP แต่ไม่พบในไฟล์ Express รอบล่าสุดต้องเปลี่ยนสถานะเป็นไม่ใช้งาน
- ห้ามลบ Supplier ที่หายจากไฟล์ เพื่อรักษาการอ้างอิงและประวัติเอกสารเดิม
- Supplier ที่กลับมาปรากฏในไฟล์ Express ภายหลังต้องเปลี่ยนกลับเป็นใช้งานและอัปเดตข้อมูลจากไฟล์ล่าสุด
- ไฟล์ Supplier จาก Express ทุกครั้งต้องเป็นข้อมูล Supplier ครบทั้งหมดแบบ Full Snapshot
- หน้า Upload Supplier ไม่รองรับไฟล์ที่ Export มาเฉพาะบางประเภทหรือบางช่วงรหัส
- การเปรียบเทียบเพื่อปิดใช้งาน Supplier ที่หายไปต้องทำหลังไฟล์ผ่าน Validation ทั้งชุดแล้วเท่านั้น
- Field บังคับสำหรับ Supplier มีเพียงรหัส Supplier และชื่อ Supplier
- ที่อยู่ เบอร์โทรศัพท์ ชื่อผู้ติดต่อ เลขประจำตัวผู้เสียภาษี Email และสาขาสามารถเป็นค่าว่างได้
- หากรหัส Supplier หรือชื่อ Supplier ว่างแม้แต่หนึ่งรายการ ต้องบล็อกการ Import ทั้งไฟล์
- เลขประจำตัวผู้เสียภาษีต้องเก็บตามค่าที่ Express ส่งมา โดยไม่บังคับจำนวนหลักและไม่บล็อก Import จากรูปแบบเลข
- ทุก field แบบข้อความต้องตัด whitespace ที่หัวและท้ายก่อน Preview และ Import
- ห้ามยุบหรือเปลี่ยน whitespace ที่อยู่ภายในข้อความในระยะแรก
- ต้องนำเลขที่บัญชีจาก Express มาเก็บใน Supplier ตามค่าที่ได้รับ แม้ยังไม่มีการใช้งานใน Phase แรก
- เลขที่บัญชีจาก Express ไม่ต้องอ้างอิงหรือตรวจสอบกับ Chart of Accounts ใน Phase แรก
- ต้องเก็บเครดิตเป็นจำนวนวันตามค่าจาก Express
- ต้องเก็บยอดวงเงินเป็นค่าตัวเลขตาม Express
- ค่าเครดิต `0` และยอดวงเงิน `0.00` ต้องเก็บตามค่าเดิมโดยยังไม่ตีความความหมายทางธุรกิจเพิ่มเติม
- ต้องเก็บประเภท Supplier จากหัวข้อกลุ่มในรายงาน Express ให้กับ Supplier ทุกรายการในกลุ่มนั้น
- ไฟล์ตัวอย่างปัจจุบันมีประเภท `ผู้จำหน่ายประจำ` สำหรับ Supplier ทั้ง 957 รายการ โดยรวมรหัสเดิมแบบมีขีด 3 รหัสด้วย

## ประเด็นที่ต้องถามและตัดสินใจ

- Express Export ออกมาเป็นไฟล์ประเภทใด
- Supplier และ Customer อยู่ไฟล์เดียวกันหรือแยกไฟล์
- ใครมีสิทธิ์ Upload และยืนยันการ Import
- ต้องเก็บประวัติการ Import และผู้ดำเนินการนานเท่าใด

## Acceptance criteria

จะกำหนดหลังได้รับตัวอย่างไฟล์และสรุปกฎข้อมูล
